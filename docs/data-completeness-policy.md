# 데이터 완전성 운영 기준

## 목적

이 프로젝트에서 `최신`과 `완전`은 같은 뜻이 아니다. 원본 갱신일이 오늘이어도 일부 지역만
제공하거나 좌표가 틀리면 지도 데이터로는 불완전하다. 반대로 오래된 원본이라도 제공기관이
그 뒤 자료를 공개하지 않았다면 앱 오류가 아니라 `공급원 노후화`다.

앱과 운영 문서는 다음 여섯 축을 서로 분리해 기록한다.

1. **시간**: 원본 행 기준일, 공식 메타데이터 갱신일, 앱 생성일
2. **범위**: 전국, 앱 지원 9개 시도, 특정 시도, 특정 소방서·시군구
3. **지도 사용성**: 원본 행 수, 유효 좌표 행 수, 좌표 미확인 행 수
4. **레코드 무결성**: 고유 키 중복, 삭제·사용중지 상태, 스키마 누락
5. **대조**: 공개 API 수와 보도자료·관리대장 발표 수의 일치 여부
6. **운영 증거**: 동기화 코드 존재, 로컬 검증 통과, 실제 workflow 실행 성공을 별도 기록

## 절대 규칙

- 제공되지 않은 2025·2026 값을 추정하거나 0으로 만들지 않는다.
- 집계표만 최신인 자료로 시설 점 지도를 덮어쓰지 않는다.
- 특정 시군구 자료를 시도 전체 최신 자료처럼 표시하지 않는다.
- 주소 지오코딩 결과를 안전시설의 실제 좌표로 단정하지 않는다.
- 범위를 벗어나거나 숫자 형식이 깨진 좌표는 지도에서 제외하고 원문 값을 별도 보존한다.
- 이전 원본 좌표를 사용할 때는 시설유형과 공식 주소가 정확히 일치하고 후보 좌표가 하나로
  수렴할 때만 허용하며, 원본 날짜와 보충 사실을 함께 기록한다.
- 공식 원본의 중복은 임의 삭제하지 않는다. 고유 키가 아닌 것으로 확인되면 원본 행을
  보존하고 중복 개수와 병합 키의 한계를 표시한다.
- 공개 API와 공식 발표 수가 다르면 차이를 그대로 공개하고 누락 행을 만들지 않는다.
- 수동 기준일을 사용한 경우 `sourceDateSource=workflow manual override`로 남긴다.

## 상태 판정

| 상태 | 의미 |
| --- | --- |
| `complete` | 선언한 범위에서 행·좌표·대조 검사가 모두 통과 |
| `scoped` | 선언한 지원 범위는 충족하지만 전국 자료는 아님 |
| `partial` | 좌표 누락, 관할 일부 최신화, 혼합 기준일 등 알려진 공백이 있음 |
| `upstream-mismatch` | 앱 변환 문제가 아니라 공식 원천끼리 수량이 불일치 |
| `stale` | 원본 기준일이 데이터별 허용 기간을 초과 |

`stale`은 다른 상태와 동시에 존재할 수 있다. 예를 들어 소방용수는 앱 지원 9개 시도
범위가 있으면서도 전국 표준 원본이 2024년이고, 광산구만 2026년 지역 원본을 적용한
`partial + stale` 상태다.

## 새 원천을 합치는 순서

1. 정부·지자체 공식 페이지인지 확인한다.
2. 재배포·변환 허용 범위를 확인한다.
3. 기준일과 공간 범위를 행 수준으로 확인한다.
4. 지도 자료는 WGS84 좌표 또는 검증 가능한 원좌표계를 요구한다.
5. 전체 교체인지 시도·시군구·소방서 단위 교체인지 선언한다.
6. 행 수 급감, 타입 합계, 지역 합계, 중복 키, 좌표 경계를 검사한다.
7. 기존 자료보다 최신인 관할만 교체하고 나머지는 유지한다.
8. manifest와 세 사용자 화면에 범위·좌표 누락·대조 차이를 표시한다.
9. 단위 테스트, 데이터 감사, 실제 렌더러 E2E를 통과시킨다.
10. 배포 후 workflow 성공과 운영 파일의 해시·수량을 별도 확인한다.

## 제품 범위 결정이 필요한 부분

현재 시설 지도는 9개 시도 지원을 제품 범위로 삼고 있다. 완전성 목표는 둘 중 하나를
명시적으로 선택해야 한다.

- **9개 시도 보증형**: 현재 지원 범위의 좌표·최신성·기관 대조를 먼저 높인다.
- **전국 확장형**: 17개 시도로 늘리되, 지역별 공개 격차 때문에 초기에는 더 많은
  `partial` 상태와 기관 요청이 생긴다.

운영상으로는 9개 시도 보증형을 먼저 완결한 뒤, 지역 하나씩 같은 검증 게이트를 통과시켜
전국으로 넓히는 방식을 기본안으로 둔다.

## 외부 요청 원칙

기관 요청은 보내지 않고 공개 인터넷 원천을 먼저 사용한다.

- 지역별 화재피해는 NFDS 공개 조회로 2024~2026 시도×월 집계를 확보했으므로 별도 요청이
  필요하지 않다. 다만 이를 사건별 주소·관할서 자료로 가장하지 않는다.
- 경북 위험물은 소방청 공개본으로 2024·2025 도 합계를 확보했다. 2024 소방서별 상세는
  경상북도 통계연보에서 확인되지만 변경금지 조건이라 앱에 전재하지 않고, 재가공 가능한
  KOSIS 2023 상세를 유지한다.
- 2026 구급은 현재 확정 시도·소방서 자료가 공개되지 않았다. 2025 확정 통계와 2026 잠정
  전국 일일 상황을 같은 계약으로 합치지 않고, 공식 공개본을 기다린다.
- 지진해일 680개소 발표와 공개 API 647행의 차이는 공개 명부가 나오기 전까지 그대로
  표시한다. 다른 지도에서 이름이 비슷한 행을 가져와 33곳을 만들지 않는다.
- 소방용수·공중화장실은 좌표와 재배포 조건이 확인된 지자체 공개자료만 관할 단위
  오버레이로 적용한다.

공중화장실은 요청서나 별도 API 키 없이 LOCALDATA 전국 CSV를 기준 목록으로 사용한다.
좌표는 서울 OA-22586, 제주시 15110521, 부산 동래구 3079086의 공식 CSV와 부산
갈맷길 15084238의 공식 SHP에서 보충한다. 자동 결합은 관할 좌표 경계를 통과하고
중앙·지역 양쪽에서 정규화한 시설명과 도로명 또는 지번주소가 고유하게 1:1로 일치한
경우만 허용한다. 이번 보충은 서울 601곳, 제주시 326곳, 동래구 39곳, 부산 갈맷길
24곳이다. 서울 공식 자료와 엄격히 다시 일치한 기존 주소 대표점 3곳은 신규 보충 수에
더하지 않고 시설 좌표로 정밀도만 개선한다.

부산 도로명주소 정보 15028854는 화장실 좌표가 아니라 건물 대표점이므로 별도
`address_point` 계층으로만 사용한다. 중앙 도로명주소와 공식 원천 주소가 단일행으로
정확히 일치하고 건물명이 대조된 신규 222곳을 추가하고, 부산 밖을 가리키던 기존 v1
오류 좌표 13곳은 옛 값을 보존한 뒤 같은 계층으로 교정한다. Kakao 주소 지오코딩 캐시
696곳과 같은 주소 좌표를 이어받은 새 관리번호 2곳까지 합친 기존 주소점은 698곳이며,
시설명이 다른 새 관리번호가 동일 주소의 과거 공식 시설 좌표를 이어받은 45곳도 우선
주소 대표점으로 강등한다. 이 중 서울 최신 공식 지역 자료와 시설명·주소가 다시 1:1로
맞는 3곳은 시설 좌표로 승격한다. 남은 동일 주소 이전 좌표 42곳을 포함한 전체 주소
대표점은 975곳이다. 화면은 이를 시설 좌표 10,679곳과 구분하며
실제 화장실 위치·층·출입구와 다를 수 있음을 표시한다. 나머지 5,669곳은 미확인으로
남겨 추정 좌표로 가장하지 않는다.

2026-07-30 공개 인터넷 추가 조사에서는 대전 중구 2024 파일과 울산도시공사 2025
파일이 모두 엄격 일치 0건이었고, 대구 공식 SHP는 실제 행 갱신일이 2015~2016년이라
최신 오버레이에서 제외했다. 좌표가 없는 2025·2026 표와 서비스 키가 필요한 API도
좌표 원천으로 간주하지 않는다.
